# Overview

The Docs standards: documentation rules and templates.

- [Application Template](application-template.md) - per-app overview (users, features, views) and architecture
- [Docs Are Hierarchical, Explicit And Short](docs-are-hierarchical-explicit-and-short.md) - summary, contents with a fitting heading, a heading or page per item, name things outright
- [Docs Describe Behavior, Not Wiring](docs-describe-behavior-not-wiring.md) - describe behavior, not code wiring
- [Docs Folder Structure](docs-folder-structure.md) - root overview and architecture. Development, workspace, features. Every record under one records folder
- [Docs State Knowledge](docs-state-knowledge.md) - knowledge pages state what is true, without provenance
- [Documentation Philosophy](documentation-philosophy.md) - product-level, brief, one purpose per file, plain punctuation, reproducible from the docs
- [Feature Spec Template](feature-spec-template.md) - spec use cases with stable ids. Start state, action, confirms
- [Feature Template](feature-template.md) - a feature doc: summary, contents, a heading per item, aesthetics, edge cases. Functional only, no UI copy, use cases live in the spec
- [File Names](file-names.md) - a file is named after its title, in lowercase, with dashes
- [Glossary](glossary.md) - the terms a project uses most, one entry each, described in plain words
- [Library Feedback](library-feedback.md) - library friction is surfaced to the director in the report, or filed with a library the project contributes to, never kept as a doc in the project. A workaround gets a why-comment
- [No Faux Headers In Lists](no-faux-headers-in-lists.md) - no bold-label bullets. Promote them to headings
- [UI Vocabulary](ui-vocabulary.md) - functional UI names: drawer, sheet, never 'surface'
- [Workspace Levels](workspace-levels.md) - a maturity scale for a workspace, from unknown to suite complete
- [Workspace Suite](workspace-suite.md) - the deliverables of a complete workspace
- [Workspace Template](workspace-template.md) - workspace docs: functional overview, technical architecture, concern docs
